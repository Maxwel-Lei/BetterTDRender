## 1. 多光源（点光源、聚光灯、多盏平行光）

### 1.1 现状和目标

- 现状：Lights 匹配到的灯只用第一盏平行光，点光、聚光被当成平行光（只取方向）。
- 目标：
  - TD 的三种 Light COMP 都按它自己的参数工作：`point`、`cone`（聚光）、`distant`。
  - 读这些参数：
    - 颜色、Dimmer
    - 衰减：`attenuated`、`attenuationstart / end / exp`
    - 聚光：`coneangle / conedelta / coneroll`
    - 投影贴图：`projmap`，即灯光遮罩（gobo）
    - 阴影：`shadowtype`、`lightsize1/2`
  - **零配置**：灯放进 Lights 匹配的范围就生效，不加槽。

### 1.2 分工

| 灯 | 处理 |
|---|---|
| 主光（第一盏平行光） | 现有路径不变：PCSS 软阴影、雾的光束、SSS 透射、探针 GI |
| 其他平行光（最多 4 盏） | 无阴影，直接循环计算 |
| 点光、聚光（最多 64 盏） | 分块裁剪（§1.3）；按灯自己的 Shadow Type 决定是否投影，受阴影预算限制（§1.4） |

### 1.3 计算方式

- 每帧把灯的参数写成一张**灯光表**（纹理缓冲，和体积雾读 uniform 的方式一样），不占 `uB` 槽位。每盏灯 4 个 vec4：
  - 位置 | 范围
  - 颜色 × 强度 | 类型
  - 朝向 | 内外锥角
  - 阴影 / 投影贴图编号 | 衰减指数
- **第一阶段**：8 盏以内在 composite 里直接循环所有灯，简单、可靠。
- **第二阶段**：加一个计算着色器做**分块裁剪**。按 16×16 像素分块，用块内的深度范围判断每盏灯会不会照到这块，写出每块的灯光列表；composite 只算本块的灯。体积雾复用 froxel 格子做同样的分配，雾里出现点光、聚光的光晕和光束（M3 遗留项）。
- **衰减**：默认“和原生一致”，按 TD 的 Attenuation Start / End / Exp 算，和原生 Render TOP 并排对比调到一致。另提供 Falloff = Physical：平方反比 + 平滑窗口（Frostbite / UE 的公式），亮度跟着距离走更真实。
- **聚光**：内外锥角平滑过渡；`projmap` 作为灯光遮罩，最多 4 张，放进一个纹理数组。

### 1.4 阴影

- 灯自己的 **Shadow Type 不是 Off** 才投影，和原生的习惯一致。
- 预算参数 **Max Shadowed Lights**，默认 4。超出时按到相机的距离挑最近的几盏，Status 提示。
- **聚光灯**：透视阴影图，放进一张阴影图集（Shadow Atlas），4096² 分成 4 块。
- **点光源**：立方体阴影（Cube Map），6 个面。默认质量较低，开销提示写进手册。
- **缓存**：沿用主光的做法，灯和物体没动就不重画（`SHADOW.CACHE`），静止场景零开销。
- **CPU 风险**：每个额外的 Render TOP 约 0.3 ms CPU。要先验证 TD 的 Render TOP 能否一次画多个相机（多相机渲染到纹理数组）或直接画立方体贴图，见 §6 的验证项 S1。

### 1.5 和其他功能的配合

| 功能 | 处理 |
|---|---|
| SSS 透射 | 点光、聚光也算透射；没有阴影的灯按 Thin 的方式近似 |
| 体积雾 | 第二阶段：每格累加局部灯的散射，有阴影的灯带阴影 |
| 探针 GI | 局部灯计入探针（灯移动时重算探针，和主光一样） |
| 折射 / 玻璃 | 玻璃表面加局部灯的高光 |
| Debug View | 新增 Light Count（每块的灯数热力图）、Local Lights（只看局部灯） |

### 1.6 界面（Light 页新增一节）

| 参数 | 默认 | 说明 |
|---|---|---|
| Local Lights | On | 局部灯总开关 |
| Light Count | 只读 | 例：`1 main, 6 point, 2 cone (2 shadowed)` |
| Max Lights | 32 | 上限 64 |
| Max Shadowed Lights | 4 | |
| Local Shadow Resolution | 1024 | 每盏灯（每个面）的分辨率 |
| Falloff | Match Native | 或 Physical |
| Local Intensity | 1 | 局部灯整体亮度倍数 |

### 1.7 验收和开销

- **对比原生**：点光、聚光的亮度分布和原生 Render TOP 一致，衰减曲线、锥角边缘都对齐。
- **新测试 `m9_lights`**：
  - 没有局部灯时旁路，画面和 0.8 完全一样；
  - 16 盏无阴影灯；
  - 2 盏有阴影的聚光；
  - 1 盏点光阴影；
  - 灯移动时阴影跟上；
  - 无 NaN。
- **开销目标**（1080p High）：16 盏无阴影灯 GPU +0.4 ms；每盏有阴影的灯在移动时 CPU 约 +0.3 ms，静止时 0。

## 2. 物体运动矢量

### 2.1 现状和目标

- 现状：运动模糊、TAA、屏幕空间效果的时间累积，都只用相机运动重投影；物体自己动时没有运动模糊，还会轻微拖影。
- 目标：
  - 动的物体有逐物体运动模糊；
  - TAA 和时间累积按物体速度重投影；
  - 静止的场景零开销。

### 2.2 做法

- **哪些物体在动**：`uniforms` 每帧比较每个镜像物体的世界变换，再看实例化源和 SOP / POP 是否在变。思路同阴影缓存的 `shadow_watch`。
- **速度缓冲**：新加一个 Render TOP `velocity`，只画“这一帧动过”的物体（Unity HDRP 的做法）。它的材质读物体上一帧的矩阵，这个 uniform 只在物体动的时候更新，所以只有动的物体的材质重算。G-Buffer 材质仍然不读每帧数据（`GBUF.SHARED` 不破）。
- **合成**：速度 = 有物体速度的像素用物体速度，否则用相机运动加深度算。
- **实例化和粒子**（难点）：
  - 实例化：用 Cache CHOP / Cache POP 保存上一帧的实例变换。
  - POP 粒子：用上一帧的位置属性。
  - 都要先验证，见 S2。做不到的情况先只给运动模糊，不给 TAA 修正。
- **用到速度缓冲的地方**：
  - 运动模糊：改成 McGuire 的重建滤波，带瓦片最大速度；
  - TAA：重投影，取最近深度处的速度；
  - SSGI / SSR / 光追反射的时间累积。

### 2.3 验收和开销

- 测试场景：旋转的风扇、平移的球、实例化的方块阵列。
  - 物体边缘不拖影，TAA 后的残影比 0.8 少；
  - 运动模糊方向正确；
  - 静止时 `velocity` 不计算。
- 开销：有物体在动时 CPU 约 +0.3 ms、GPU 约 +0.1 ms；静止时 0。
- 顺带的 M2 遗留项：镜头切换自动检测（画面突变时重置历史）、景深散景形状，放到这一阶段后面，看时间决定做不做。

## 3. 贴图坐标和场景比例

### 3.1 贴图坐标（0.8.3 已完成，见 `IMPLEMENTATION_2.md` §11b-6）

TD 里没有“平铺 / 偏移”参数，平铺靠几何体的 UV（Texture SOP）。BTDR 目前缺的是：

| PBR MAT 参数 | 现状 | 改成 |
|---|---|---|
| 每张贴图的 Extend U / V（Repeat / Zero / Hold / Mirror） | 统一用默认的 Repeat | 绑到 GLSL MAT 对应采样器的 Extend（静态表达式） |
| 每张贴图的 Filter | 统一线性 + 4× 各向异性 | 跟随材质（保留 4× 各向异性） |
| 每张贴图的 Texture Coordinates（第几套 UV / 指定属性） | 只用第一套 UV | 支持第二套 UV（光照贴图、AO 贴图常用） |
| 实例的 Instance Texture Coordinates（实例各自的 UV 偏移） | 不读 | 用 TD 的实例纹理坐标函数（验证项 S3） |
| Height Map / Parallax、Rim Light | 不读 | 这一版仍不做，写进限制 |

### 3.2 场景比例（0.8.3 已完成）

- Render 页新增 **Scene Unit**：Meters（默认，等于现在的行为）/ Centimeters / Millimeters / Inches / Custom（每单位多少米）。
- 所有“以米为单位”的参数在 `uniforms` 里统一换算成场景单位：
  - AO / GI 半径，Height-Field AO 半径；
  - SSR 最大距离、厚度；
  - 雾的浓度、高度、最远距离；
  - SSS 半径（Scatter Scale 变成在它之上的额外倍数）；
  - 折射的吸收距离；
  - 阴影偏移；
  - 探针最小间距。
- 景深的对焦距离本来就按场景单位，不变；传感器宽度、焦距按毫米，不受影响。
- **验收**：同一场景按厘米建（所有长度 × 100）并设 Centimeters，和按米建的画面差小于 1%（实测 0.13%）。

## 4. 实例化几何体进光追

- **现状**：实例化的物体不进光追代理，粒子、阵列不挡光、不出现在光追反射里。
- **做法**分两种情况：
  - 少量实例（总三角形在预算内，默认 20 万）：用 Copy POP 按实例变换把减面后的模型复制进代理，实例颜色取 Instance Color。
  - 大量实例（粒子）：超出预算就跳过，Status 提示。
- **更好的路**：如果 TD 的 GLSL POP 加速结构支持实例（一个模型建一次、实例只存变换，即 DXR 的两层结构），就直接用它，没有三角形预算问题，要先验证（S4）。
- **会动的实例**：每帧用 Fast Build 重建，开销按三角形数线性增长，写进手册。
- **验收**：实例化的 10×10 柱子阵列挡住探针 GI、出现在光追反射里；20 万三角形预算内，重建加速结构的 GPU 时间小于 0.3 ms。

## 5. 正交相机、点精灵

### 5.1 正交相机

- **现状**：只支持透视相机，正交相机会给出警告。
- **做法**：
  - `common.glsl` 加统一的 `viewRayOrigin(uv)` / `viewRayDir(uv)`：透视时起点是相机位置，正交时起点在近平面上、方向固定。
  - 所有从深度重建位置、发射屏幕射线的 pass 都改用它：光照背景、SSR、SSGI、雾、折射、TAA 重投影。
  - 景深在正交下关闭。
  - 雾的深度切片改成线性分布。
- 透视 / 正交混合（`persporthoblend`）、自定义矩阵不支持，给出警告。
- **验收**：正交相机下每个效果都有画面、无 NaN，几何检查（深度重建世界坐标）误差小于 0.01。

### 5.2 点精灵

- **现状**：没测过。用点渲染的粒子（POP 粒子、点云）大概是一个像素大小的平面点。
- **做法**：G-Buffer 材质里遇到点图元时，用 `gl_PointSize` 按距离设大小，在像素着色器里用 `gl_PointCoord` 画成一个有正确法线和深度的小球（球体冒充），能正常受光、投影、进 SSR。点的大小来自粒子的大小属性，或一个全局参数。
- **验收**：100 万个点的粒子画成受光的小球，GPU 开销小于同样数量的实例化小球的一半。验证项 S5：TD 的 Render TOP 画 POP 点时，GLSL MAT 里 `gl_PointSize` 是否可写。

### 8.1 研究 Josef Pelz 插件后的改进项（2026-11-22）

来源：拆解 Pathtracer 3.1.1 和 T3D 1.14.1 的内部网络和着色器（报告 https://claude.ai/artifact/14rogoJdJBNFmhNeyVu6kN，笔记 `JP-Pathtracer-拆解笔记.md`）。只借鉴方法，代码自己写；方法都来自公开论文。

| 编号 | 内容 | 现状（2026-11-22 查过代码） | 放进哪个版本 |
|---|---|---|---|
| J1 | **粗糙金属的能量补偿**：单次散射的 GGX 粗糙度高时偏暗，按预计算的能量表（或解析拟合）乘 `1 + F0 · (1/E − 1)` 补回多次微表面反射（Kulla & Conty 2017 / Turquin 2019）。用在环境光、光追反射、直接光的镜面项 | 没有。`lighting_core.glsl` 和 `refract.frag` 用的是 Karis 的解析近似 `envBRDFApprox`，不带补偿 | 0.8.4 |
| J2 | **路径追踪参考图对比工具**：同一场景用 Pathtracer 累积到收敛，作为物理正确的参考，和 BTDR 逐项并排（GI、AO、雾、SSS、玻璃），写成 `tools/pt_reference.py`，结果进实现文档，用来校准默认参数。只在本机测试用，不分发 Pathtracer | 现在的测试只和原生 Render TOP 比，原生没有 GI，不算正确答案 | 0.8.5（工具版本，不改渲染） |
| J3 | **雾里的局部灯用等角采样**（equiangular sampling，Kulla & Fajardo 2012）；光追 GI 里按“功率 ÷ 距离²”随机挑一盏局部灯，不逐盏都算 | 雾只算太阳和环境 | 并进 0.9.1 |
| J4 | **折射区域的运动矢量**：玻璃后面的物体在 TAA 里拖影，是因为运动矢量取的是玻璃表面的。按屏幕空间折射偏移修正运动矢量，加上 G1 的响应遮罩（Pathtracer 是在上一帧里迭代搜索，BTDR 用简化版） | 没有 | 并进 0.9.2 |
| J5 | **雾的多次散射和双瓣相位函数**：倍频近似（Wrenninge 2013：Σ aⁿ·phase(cⁿg)·T^(bⁿ)，a ≤ b），浓雾不发灰；前向 + 后向两个 Henyey–Greenstein 瓣 | 已经用 Hillaire 的能量守恒积分（`fog_integrate.comp`，这一项不用改）；单瓣 HG，没有多次散射 | 并进 0.9.1 |
| J6 | **接 T3D 的体积**：雾加一个“密度体积”输入，读 3D 纹理（T3D、或任何 3D 纹理 TOP），按体积的盒子变换采样到 froxel；可选自发光通道和黑体辐射色。这样 fluidT3D 的烟火能带 BTDR 的阴影、GI 和体积光渲染 | 没有 | 0.9.6（0.9.5 给了用户提的跟踪对焦） |
| J7 | **球幕 / 全景输出**（鱼眼、等距柱状、立方体贴图） | 没有；延迟渲染要画 6 个面，GPU 开销接近 6 倍，超出预算 | 以后评估 |
| J8 | **DLSS 超分辨率**（C++ TOP 接 NVIDIA NGX） | 没有；要写和维护 C++、只支持 RTX、要审 NVIDIA 的再分发条款 | 功能稳定、确定商业路线之后再评估 |

不学的：把 BTDR 拆成一组专用算子（BTDR 的卖点是拖进去就能用、材质用原生 PBR MAT）；追求完全物理正确（那是 Pathtracer 的路，BTDR 的目标是预算内出 UE5 观感）。
